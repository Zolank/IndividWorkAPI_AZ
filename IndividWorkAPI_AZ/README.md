# Автоматизация тестирования GitHub REST API

Данный проект представляет собой фреймворк для автоматизированного тестирования REST API GitHub. Проект разработан на языке Java с использованием современных инструментов тестирования и реализует полный жизненный цикл ресурса (создание, получение, обновление, удаление репозитория).

## 🛠 Технологический стек

* **Java 11+** — основной язык программирования.
* **Maven** — система управления зависимостями и сборки проекта.
* **RestAssured** — библиотека для тестирования REST API.
* **TestNG** — тестовый фреймворк (используется для запуска тестов, приоритезации и DataProvider).
* **Jackson (Databind)** — для сериализации и десериализации JSON в DTO.
* **Lombok** — для сокращения boilerplate-кода (геттеры, сеттеры, билдеры).
* **SLF4J** — для логирования процесса выполнения тестов.

## 📂 Структура проекта

Проект спроектирован с учетом лучших практик построения фреймворков и избегания дублирования кода:
* `src/main/java/api/models` — DTO-классы для маппинга ответов API (например, `RepositoryDTO`).
* `src/main/java/api/clients` — базовые классы (`BaseGitHubClient`), инкапсулирующие настройки HTTP-клиента, авторизацию, логирование и **обобщенный (generic) механизм десериализации**.
* `src/main/java/api/utils` — утилитарные классы (например, `HeaderUtils` для валидации заголовков).
* `src/test/java/tests` — классы с автоматизированными тестами, разделенные логически.

## 🚀 Предварительная настройка (ВАЖНО)

Для успешного запуска тестов проекту требуется доступ к вашему аккаунту GitHub. В целях безопасности **токен не хранится в исходном коде**.

1. Сгенерируйте **Personal Access Token (classic)** в настройках GitHub (Developer settings).
2. Убедитесь, что токену выданы права (scopes): `repo` и `delete_repo`.
3. Установите токен как переменную окружения (Environment Variable) в вашей ОС или среде разработки:
    * **Имя переменной:** `GITHUB_TOKEN`
    * **Значение:** `ghp_ваш_сгенерированный_токен`

## 🏃‍♂️ Запуск тестов

### Через IntelliJ IDEA:
1. Откройте класс `GitHubRepoTests.java`.
2. В настройках конфигурации запуска (Edit Configurations) добавьте переменную окружения `GITHUB_TOKEN=ваш_токен`.
3. Запустите класс с помощью зеленой кнопки Run.

### Через командную строку (Maven):
Убедитесь, что переменная `GITHUB_TOKEN` экспортирована в терминале, затем выполните команду:
`mvn clean test`

## 🏆 Реализованные требования для максимальной оценки (Пункт 9)

В рамках данного проекта реализованы следующие продвинутые механики:
1. **Параметризованные тесты:** Использован `@DataProvider` из TestNG для проверки создания нескольких репозиториев с разными данными в одном тесте.
2. **Обобщенный механизм десериализации:** В базовом клиенте реализован generic-метод `<T> T deserialize(...)`, исключающий дублирование кода при парсинге JSON в DTO.
3. **Логирование:** Использованы `RequestLoggingFilter` и `ResponseLoggingFilter` для прозрачного вывода всех запросов и ответов в консоль.
4. **Управление жизненным циклом (Teardown):** Реализован метод с аннотацией `@AfterClass`, который гарантированно удаляет все созданные во время тестов репозитории, возвращая систему в исходное состояние, даже если часть тестов упала.
5. **Дополнительный негативный сценарий:** Реализован тест, проверяющий поведение API (статус 422) при попытке создать репозиторий с уже существующим именем.
